# Play Calindra Strike

Coordinates: -z is norte, +x is leste. Game time keeps running while you think, so keep the `wait` loop tight (gaps of 20–30 s cost a large part of a round).

## Setup

- Play in a background subagent when the harness has them, so the main thread stays free; play directly otherwise. One MCP connection is one player: if the main thread already joined, `leave` first, and a second `join` on one connection returns the same character. Claude subagents share the session's single connection, so more Claude players need one `node tools/mcp/launch.ts` each behind a TCP broker (see Connection). If another controller drives the same connection, `leave` + `join` with a new name can work for one moment and then the connection is taken over by a different player (seen: joined as `harnessBigPickle`, the next state was `OC-BigPickle` with a new id and another player's score). Re-read `you.name` and `you.id` on every state and key podium results by the id you actually control, not by the requested name.
- A match needs `WARMUP_MIN_PLAYERS` players (default 2); a lone player never leaves `warmup`, so make sure someone else is on the server (another player, `BOT_FILL`, dev bots).
- Read this file first and follow it over any summary in the brief. Do not end your turn after `join`: keep the `wait` loop going until the podium, then `leave`.
- Names: at most 16 characters (`Claude-Haiku5.5-B` was rejected, `Claude-Haiku5.5B` works), distinct per player, agent plus model (`Claude-Haiku5.5`, `Codex-GPT6`). A taken name gets `#2`, `#3`; read `you.name` and `you.id` from state, and never hard-code the id (it changes on every `join`).
- Codex players run in a sandbox that blocks localhost TCP (`connect EPERM 127.0.0.1:<port>`), so they cannot use the broker: give them the native `calindra-strike` MCP server from `~/.codex/config.toml` (each Codex process spawns its own `launch.ts`, so each is a separate player). The `codex:codex-rescue` wrapper backgrounds a long play task and ends at once; to keep one visible subagent per Codex player, add a small Claude subagent that polls `codex-companion.mjs status <job>` with sleeps under 3 minutes (a 240 s sleep stalled one for 600 s) and returns the result.
- Codex players can only call allowlisted tools (`get_state`, `join`, `hunt`, `say`, `radio`, `wait`, `reload`, `choose_loadout`, `leave`); the rest fail with `MCP tool call requires approval, but approval policy is never`. They play with `hunt` only, which already pursues flags in CTF and plants and defuses in debug defusion (`use` is not on that allowlist). Do not retry a refused tool or bypass it with `--write`.
- To stop a player: `TaskStop` the agent, then `leave` on its connection (a stopped agent leaves its player in the match).

## Core loop

- Free aim and hearing: `aim` holds the crosshair on a world point `{ x, y, z }` or an angle `{ yaw_deg, pitch_deg }` (pitch up positive, yaw as in `you.yawDeg`) with the pilot standing still, and answers with `expect`, the material and surface a shot would hit. `fire { ms }` holds the trigger (a short press is one shot with a semi-automatic weapon). A `move_to`, `attack`, `hunt` or `stop` hands the view back to the pilot. `get_state.sounds` lists what you heard since the last read (`shot`, `impact` with material and surface, `hurt`) with `distance`, `bearingDeg`, `intensity` 0 to 1 and `loudness`; your own shots are inferred from the magazine dropping, and sounds under 0.08 are dropped. To shoot objects, `aim` at a cover `pos` from `scene.cover` or the point in `scene.facing`, `fire`, then read `sounds`. Random shots in `Forja` land on ground 35%, charcoal 28%, concrete 18%, crate 11%, container 7%; glass and plants never stop a bullet, so they make no impact sound.

- `join`, then read `phase`, `mode`, `team`, `you.intent`, `score`.
- Set `hunt` to roam and fight. It survives respawns but a new live round resets it to `idle`: check `you.intent` at every phase change and reissue it.
- The server kicks a player after 60 s with no input (`IDLE_KICK_SECONDS`, default 60; the operator can change it or turn kicks off with `IDLE_KICK=0`). For an MCP player any tool call counts as presence, `wait` included, so a tight `wait` loop is enough. What trips it is a long gap between calls: slow thinking, a slow harness command (see Slow harness commands) or an approval prompt waiting for a human.
- A kick reaches you as an error on your next tool call, `Kicked for inactivity: ... Call join to play again.` (`Left game` is what you get after your own `leave`). The kicked player is gone from the match, so `join` again, which gives a new id, and reissue `hunt`. The ready-screen kicks (`afk`, `podium`) cannot hit an MCP player, because `join` confirms ready by itself and again whenever the server asks after a podium. Do not retry the failed tool in a loop, since every call until the `join` returns the same error.
- `wait` takes `{ ms: 100..5000 }` (5000 is practical). Each read drains `events` and `chat`, so count kills from `score`, not by summing events, and read `chat` on every read.
- Finish with `leave` after the podium (`phase: closed`). After `leave`, `get_state` answers `Left game` (plain text, not JSON). Do not vote unless asked.
- `Left game` can also appear on the first `wait`/`get_state` after a podium even without calling `leave`: the connection drops during the transition. Check `curl -s http://127.0.0.1:7350/status` for a live round and `join` again with a fresh name/id; the next match counts normally. Capturing the podium in the same polling call that sees `phase: podium` is essential, because that dropped connection cannot report it afterwards.
- Merge what you learn into this file (a tool behaviour, a map pattern, a tactic that worked or failed) and keep the existing sections.

## Counting matches

- Wait for `phase: live` before joining. A join during `podium` shows the previous match's results.
- A match counts only if you joined `live` with about 60 s or more left, stayed to the podium and saw it. For a sample that says something, join with 180 s or more left or at round start: CTF ends at 3 captures (often within a minute), debug defusion at 5 points (`DEFUSE_SCORE_LIMIT`) and TDM at the score limit (often 110–140 s early), and players who joined with 73–78 s left got an empty sample.
- A podium lasts about 15 s. A wait batch or a slow command can jump over it into the next round, so capture the full `results` right when `phase` is `podium` (before another wait) and count each match once, keyed by its results; reset the key when `phase` returns to `live`. `endsInMs` during a podium is the podium's own timer.
- A connection that stays through a podium is put in the next round without a new `join`, possibly on another team (seen 1→0 and 0→1, also mid-TDM from rebalancing) or another map. Re-read `map`, `mode`, `team`, `enemy`, and read the final team from the podium.
- `Socket closed`, `restart` or `Versão desatualizada` mean the round was interrupted and does not count; `join` again (see Connection for stale clients).
- Podium `results` per player: `id, name, kills, deaths, hs, best, team, bot` (plus `vote`, `next`); `winner` is the team index, `-1` for FFA and TDM ties. In FFA everyone is `enemy: true` with `team: -1`. Read final numbers from `results`, not from events.
- Several players from one host share `map`, `mode`, `winner` and `results` at podium and can run concurrently. When two agents play together, verify both IDs are in the same match.

## Targeting

- Decide by `enemy` and `team`, never by name (agents have similar names). `enemy` and `team` can change between rounds and during TDM rebalancing, so read `enemy` on every state.
- `attack` takes only `{ "target_id": <int> }` (`id`, `target`, `name`, `{}` fail with "Unexpected or missing argument"). It needs the target in `others` when sent and ends when perception is lost ("Target not currently perceived", `ended: true`); then use `lastSeen` with `move_to`, or `hunt`.
- After you die, `you.intent` keeps the old `moveTo`/`attack` until the respawn; reissue `hunt` once alive. Intent kinds: `hunt`, `attack`, `moveTo`, `stop`, `idle`.
- Do not chase enemies beyond ~1000 units and do not fight below ~50 HP; wait for the enemy to come closer.

- Loadout options, for your own choice (nothing here is a required pick; vary between matches and from your teammates, and do not announce your loadout in chat). Values from `shared/src/weapons.ts`:

  | Weapon | How to get it | Damage | Fire rate | Magazine / reserve | Reload | Speed | Best at |

  | Forja R7 (rifle) | `choose_loadout { primary: "rifle" }` | 36, ×4 head | 10/s auto | 30 / 90 | 2.5 s | 221 | mid and long range, all-rounder |
  | Brokkr SMG | `choose_loadout { primary: "smg" }` | 26, ×4 head | 12/s auto | 30 / 120 | 2.1 s | 240 | close and mid range on the move, fastest primary |

  | Mjölnir (AWP) | airdrop only | 115 | 0.7/s bolt | 10 / 20 | 2.5 s | 210 | long sightlines, scoped and still |

  Speed is units/s while running with that weapon out. Ideas, not rules: a defender holding a door can take the shotgun, a roaming hunter the SMG, a player covering long lanes the rifle.
- `choose_loadout` (rifle, SMG, shotgun) applies on the next spawn. Right after `join` it worked in one round and not in another, so read `you.slots` after the next spawn. Loadout makes no clear difference (pooled over four Haiku 5.5 high players: SMG 49 headshot kills of 62, rifle 65 of 86). Under `hunt` the shotgun (`Trovão 12`) lost mid-range exchanges in `Escritório` and `Forja` (13/26, 3/15, 3/21): prefer rifle or SMG, shotgun only up close.
- `cycle_weapon { "direction": "next" | "previous" }` is the mouse wheel: it steps primary, pistol, hammer and wraps, and the result names the weapon it lands on.
- `switch_weapon` takes only `{ "slot": "primary" | "pistol" | "hammer" | "last" }`; `weapon` fails. `weapon` in state updates on the next `wait`. The pilot may undo a switch on the next tick. With magazine and reserve empty, `hunt` falls back to pistol or hammer. `reload` returns only action flags; confirm by `mag` in the next state (`you.mag`, `you.reserve`, `you.slots`). Reload before the magazine empties.
- Airdrops give special weapons (Mjölnir AWP, Ragnarök LMG) and armor, and last until your next death. Read `airdrops` in state (`{ x, z, distance, bearingDeg }`, no id) and do not trust fixed coordinates: drop spots differ between sessions and maps. Seen on Escritório: around `-800, 250`, `-800, -300`, `0, 300`, `800, 300`.
- `hunt` only picks up drops it passes by. To collect one, `move_to` its `x, z` (`arrived: true` can be ~50 units short, and a nearby point can be "unreachable"). Drops often vanish while you approach or are taken by an enemy first, and going for one usually means dying on the way, so go only when no enemy is near. Verify with `you.slots` and `airdrops` instead of assuming pickup. Prioritize survival after collecting one.
- Pistol, rifle, SMG, shotgun and LMG: `zoom(1)` holds ADS and `zoom(0)` releases it. ADS slows movement, tightens spread and ends sprinting. Reload, deploy and objective use interrupt effective aim and the latched request resumes afterward. Switching weapons, dying, respawning or leaving clears it. Read `you.aiming` and `you.zoom` (0/1) for effective aim, `you.maxZoom` (1) for the supported level and `you.actions.zoom` for the request. The hammer rejects zoom.
- Mjölnir: the CS table applies, not the spread formula. Standing still and scoped is accurate, crouched is perfect, running is very inaccurate; do not run and shoot. `zoom` sets scope level 0 to 2 and replaces automatic scoping until respawn.
- Melee finisher: with an enemy close and low ammo, `switch_weapon { "slot": "hammer" }` (Martelo do Eitri, reach 72 units) instead of dry-firing.

## Movement

- `jump` works only when `onGround` and alive; otherwise "No living player snapshot yet" (also if you die between the state read and the call, so retry after a fresh snapshot).
- `crouch({ on })` stays on until you stand. Whether it survives respawn was seen both ways, so read `ducked` after every spawn. Crouch when engaging at close range, stand when roaming.
- `get_state.you` also reports `stance` (`stand`, `crouch`, `prone`), `sprinting`, `sliding`, `stamina` (0 to 1), `winded` and `lean` (-1 left to 1 right), and `you.actions` echoes what you asked for. Other players sprint, slide, lean and lie down too; a prone enemy is only about 20 units tall, so aim low.
- `sprint({ on })` stays on until changed, but only runs while you move forward (`move_to`, `hunt`, `attack`) standing on the ground: speed +35 percent, stamina drains from full in about 5 s, then you are winded until it is back to 0.25 (about 6 s from empty to full). Use it to cross open ground, then turn it off before you need the stamina for a slide or a fight. `walk`, crouch, prone, going backward, a jump, a slide or firing end it, and the next shot waits about 150 ms. `you.sprinting` and `blockedBy` in the answer show whether it took.
- `slide()` is one push (up to 700 ms, 20 percent stamina) to dive behind cover at speed. Sprint first, wait until `you.sprinting` is true, then call it. The answer says `requested: true`, or `false` with the reason (not sprinting, too slow under 240 units/s, low stamina, in the air). The tool presses crouch for one command, so a latched `crouch` hides it: `crouch({ on: false })` first. Read `you.sliding` after. You come out of it low and at about 330 units/s at most, so slide to reach cover, not to approach an enemy.
- `lean({ side })` with `left`, `right` or `off` peeks around a corner without moving your feet: your eye and head hitbox shift up to 18 units, so you see the corner before the enemy sees your body, and a wall stops it short. It is forced to 0 while you sprint, slide, lie prone or are in the air and comes back when that ends. Read `you.lean` to see it reach -1 or 1. Stand still (`stop`) to hold a peek.
- `prone({ on })` is for low cover and a hitbox about 20 units tall that is hard to hit and steadier to shoot from. It only works on the ground, locks the stance for 300 ms in both directions, moves at 15 percent speed, and blocks jump, sprint, slide and lean (`jump` answers an error). A pilot that keeps moving will crawl, so use it while holding a spot and get up before you reposition. `you.stance` shows `prone` when it took.
- Spawns are a parachute drop (y near 960–1000, or 1200 on Shopping Sul Rio, which has three floors). Running `hunt` during the fall got one agent killed five times in 40 s: wait for `onGround`, crouch if an enemy is near, then reissue `hunt`. Most deaths come right after a respawn.
- Do not stay still in the open. Keep `hunt` or `move_to` active and hold a spot only briefly (scoping, waiting for an incoming enemy).
- Do not let players stand still (the user watches and dislikes idle bots). The pilot used to park on objectives in defuse; now defenders before the plant, escorts during a plant and attackers guarding a planted bug patrol a ring about 240 units around the spot, changing point every 3 s (`guardPatrolPoint` in `server/src/bot.ts`). A new round or point still resets an MCP player's intent to `idle`, so reissue `hunt` at once. When running several broker players, a watchdog process (outside the repo) that reads each player every 5 s and reissues `hunt` on `idle`, `stop` or an arrived `moveTo` (and `move_to` 150–300 units away when `pos` stays unchanged over two reads) kept them moving. Reading drains events and chat, so it steals some from the agent; keep it at that interval.
- Frozen pilot: `attack` can leave the player standing, `stop` leaves `idle`, and some players sit still even with `intent: hunt`. If `you.pos` is unchanged on two reads a few seconds apart while alive and `live`, send `jump` and reissue `hunt`. `move_to` can answer "Target unreachable on navigation grid"; pick another point or go back to `hunt`.

## Floors, lifts and supplies (Shopping Sul Rio)

- Three floors: térreo (y 0, stores and the atrium), praça de alimentação (y 192) and the Mirante (y 384, a gallery over the food court that looks out over the atrium). `you.floor` in `get_state` names yours. Escalators link térreo and the food court in the atrium and the food court and the Mirante at the two ends of the strip; a glass lift in each half serves all three floors.
- To change floor use `move_to` with `y` (the floor height; `lifts[].floors` lists them): the pilot routes by stairs, escalators or the lift. `hunt` rides them too. To ride by hand, walk into the shaft and wait for the cab: it is one shared elevator with no buttons that keeps going up and down, about 1.5 s at every floor, and you leave through a doorway while it waits at that floor (`lifts[].riding` and `secondsToTop`, an average that counts the wait). Jumping is disabled inside.
- Each Mirante has a supply stand at its middle (`supplies` in `get_state`: `floor`, `ready`, `secondsLeft`, `inReach`, `youNeedIt`). Standing on it restores health, armour and the magazine and reserve of the primary and pistol, only when you need it, then it refills 40 s later; a `supply` event says who took it. It is in the open over the atrium, so expect shots from the other Mirante and from the food court below when you stop there. `hunt` goes there on its own when hurt or low on ammunition, so an opponent can be waiting; check `others` before you commit.

## Aiming and recoil

Why: every shot adds recoil, and shots fired together climb and drift. `hunt` fires bursts of 3–9 shots with pauses too short to recover, and it empties magazines at long range (30 to 0 at over 600 units while standing). Moving, jumping and not crouching add spread; about 1 s without firing resets the recoil. This comes from reading `shared/src/weapons.ts`, `shared/src/sim.ts` and `server/src/bot.ts`; nobody has measured it in play yet.

This is here so you know the recoil exists and can play with it, not to tell you how to shoot. How you handle it is your call: pick the approach you like, mix them, or try something else and see what happens. It only asks that you stay aware of it, since firing on autopilot (`hunt` spraying a whole fight while you never look at `you.mag` or whether the shots land) is what usually goes wrong.

Things you can play with:

- Bursts and pauses: about a second without firing resets the recoil, so you can break a fight into bursts with a `stop` and a short `wait`, or keep firing and accept the drift.
- Distance: from far away (over about 600 units) most shots miss and drain the magazine. You can let the enemy come, close in with `move_to`, or shoot anyway.
- Stance: crouching tightens the spread and shrinks you, but slows you down. Moving, jumping and strafing widen the spread but are harder to hit. Crouch, move, or switch as the fight asks.
- Ammo: `reload` when you choose to, in a lull or mid-fight, knowing a dry magazine costs time. The shotgun loads one shell per step (`you.mag` goes up by 1 each time) and firing interrupts the reload with the shells already loaded; other weapons add the whole magazine at the end and keep the rounds left in the old one.
- Weapon: SMG has the lowest recoil, rifle is balanced, shotgun is strongest up close.

## Chat

- Chat budget (the user found matches too chatty): at most one message every 20–30 s per player, counting punchlines, callouts and plans together. Say nothing when a message would not change what a teammate does or would not be funny; silence is fine.
- `radio` takes `{ menu, line }` (menus `comandos`, `grupo`, `respostas`, `calindra`, `calindra-2`, lines 1-9; the tool description lists them) and sends a prepared CS-style line to your team only (everyone in ffa). Teammates see it in their feed and humans hear it spoken; enemies never do. It is the agent's voice for quick callouts (`Me cobre!`, `Inimigo à vista!`), free text stays on `say`. Received lines arrive in `get_state` `chat` with `radio: true`. A radio line counts toward the chat budget. The server drops lines over its spam guard (defaults: 1.5 s between lines, 3 per 10 s, per player) without an error, so the tool answering success does not mean the line went out; space your lines instead of bursting.
- `say` is at most 100 characters (`Invalid text` otherwise; the tool call exits non-zero), in Portuguese, playful, aimed at the match and never at a real person's private details. Provocative chat is welcome (the user enjoys distinct personas).
- Persona: one per player, never shared with another player in the session (cocky veteran, friendly rookie, sarcastic commentator, calm strategist, hot-headed trash-talker), consistent in tone, nickname or running joke for the whole match. When setting up several players, assign them yourself; a player without one picks one not in use by reading the chat. A hot-headed persona may roast aim and gameplay, never with slurs, identity or body insults, threats or private details. When unsure, tone it down.
- Kill punchlines: on a kill, `say` a short joke in your persona's voice that fits it (headshot, hammer finisher, a landmark such as `Bigorna` or `Copa`, a flag carrier stopped, a comeback). Write a new line each time and never repeat your own lines in a match; one agent that reused two lines was flagged. Seeds by persona: veteran `Anos de estrada, garoto.`, rookie `Opa, acertei sem querer!`, commentator `E lá se vai mais um pro lobby.`, strategist `Tudo conforme o plano.`, hot-headed `Essa mira tá de molho, hein?`. Use one on about one kill in three (a headshot, a hammer, a stopped carrier, a comeback), not on every kill. After a hammer kill or death, react in persona (victory lap, or a good-humored complaint or rematch challenge).
- Answer only what is addressed to you or asks for help (a "me ajuda" call, a direct challenge), briefly. Do not reply to every line in the chat, and skip hostile or personal messages.
- Callouts, separate from punchlines and never replacing them: where you saw an enemy, hold or head, with landmark names (`scene.landmarks`, for example `Armazém (NE)`) rather than coordinates (`inimigo no corredor leste`, `seguro o centro`). Read teammates' callouts and act on them. Keep teasing the enemy team in persona; coordinating does not replace taunting.
- Strategy: at the start of every round (teams can change after a podium) post one short plan naming who carries, who escorts, who defends and the route or landmark (`Plano: eu pego a bandeira, vcs cobrem o Centro`), in your persona's voice, then act on it. Do not acknowledge plans with `fechado`/`ok`; reply only to disagree (`melhor flanquear pela Bigorna`), adopt the clearest one, announce changes (`troca de plano, defendo a base`) and credit good calls. Adapt during the round: after a flag is taken, dropped or captured say who goes next; when the team keeps losing the same fight, change route, send an escort or swap a defender, justified by `get_state` (`flags`, `score.teams`, `endsInMs`). Players limited to `hunt` can still announce a role and ask teammates to cover the route. Keep strategy messages short and spaced so callouts stay readable. Merge strategies that worked or failed into this file at session end.

## Scenery in get_state

- `timeOfDay` is the map's light (`phase` `day` | `afternoon` | `night`, `next`, `blend` 0..1 into the next phase). The cycle is a look only: night does not change what you perceive or how far you see, and it does not affect tactics.

- `scene` (null while dead or dropping): `facing` is the crosshair surface (null for sky), `cover` lists nearby visible walls, boxes, windows and platforms (needs line of sight), `doors` includes openings and stairs, `landmarks` gives named places (map knowledge, no line of sight), `sprays` shows decals and authors. Lists are capped and nearest-first. The `spray` tool places one (`G`, 10 per spawn, 2 s apart, a wall within 128 units ahead of the crosshair; the server drops it silently otherwise, so check `scene.facing.spray`).

## Connection and protocol

- For another player, start a separate `node tools/mcp/launch.ts` and drive it over stdio JSON-RPC (`initialize`, `notifications/initialized`, then `tools/call`). When the native MCP tools are not connected, run one `node tools/mcp/launch.ts --url=ws://127.0.0.1:7350/ws --origin=http://localhost:5173` per player behind a small broker you write outside the repo (spawn it, do the handshake once, accept `{tool, args}` lines on a localhost TCP port, return the tool text). Use TCP ports, not Unix sockets (scratch paths exceed the 108-character limit). The same broker serves Claude and Codex subagents.
- `Versão desatualizada: recarregue a página` on every tool means the MCP client is older than the server: compare `protocol` in `curl -s http://127.0.0.1:7350/status` with `PROTOCOL_VERSION` in `shared/src/constants.ts`, then reload the plugin or use a fresh `launch.ts`. When the server restarts on a new `PROTOCOL_VERSION`, every earlier `launch.ts` is stale (`restart`, `Socket closed`, `ECONNREFUSED`, then `Versão desatualizada` on `join`): kill and restart them. `leave` does not refresh a stale client. A stale connection may also lack `jump`, `crouch`, `zoom`, `walk`, `reload`, `switch_weapon`, `cycle_weapon`, `spray`; check `tools/list`. A server that is not listening (port 7350 refused) fails `launch.ts` the same way.
- Through MCP use `jump`, `crouch` and `zoom` instead of keys; the keymap is in `README.md`.
- Slow harness commands: each command can cost 20–35 s of startup (e.g. subagent `run_command` outside the sandbox), long enough to skip the 15 s podium and leave the player `idle` in the next round. Do podium and transition polling inside the Node broker client, not in bash loops (a `for ... $(...)` loop disables command-prefix matching and hits a 60 s permission timeout): add a `watch_podium` subcommand that loops `wait({ ms: 2000 })` until `phase === "podium"`, prints `PODIUM_JSON:<json>`, keeps polling until `live`, then calls `hunt({})` (and `watch_podium_only` for the last round before `leave`). Start it when `endsInMs <= 65000`, TDM score `>= 40`, CTF captures `== 2` or debug defusion points `== 4`. Do not call `leave` while a backgrounded `watch_podium_only` is still running, since it closes the session before the podium is captured.
- Do not chain state-sensitive calls with `&&` (`reload`, `crouch`, `jump` exit non-zero with `No living player snapshot yet` or `Weapon cannot reload`, and over-long `say` exits non-zero): use `;` or handle it in the Node helper.

## Capture the Flag

- Read `flags` in `get_state`: `team`, `state` (`at_base`, `carried`, `dropped`), `carrierId`/`carrierName`, `pos`, `distance`, `bearingDeg`. Capture totals are in `score.teams`; flag events are `k: flag` with `what: take | drop | return | capture`.
- `hunt` follows objectives while fighting. Within a team, players sorted by id take one defender per four members, the rest attack. Attackers seek the enemy flag and keep advancing while an enemy is over 600 units away, then duel; a carrier keeps running home even with an enemy in sight (after first returning a dropped own flag or hunting an enemy carrier); defenders fight, guard home or chase the carrier of their stolen flag. All roles return a dropped own flag by touching it.
- Capture by bringing the enemy flag to your base while your own flag is home. Use `move_to` for explicit coordination and reissue `hunt` afterward. Callouts: `Levo a bandeira, cubram a volta`, `Nossa bandeira caiu em x,z`, `Portador inimigo em x,z`.

## Hora de almoçar

Mode `almoco`, only on `Shopping Sul Rio`. Rules in `shared/src/lunch.ts`, MCP view in `tools/mcp/view.ts` (`describeLunch`).

- Hostage rescue. Three white colleagues (Estagiário, PO, Tech lead) wait at the defenders' base. Attackers call them and lead them to a restaurant counter in the upstairs food court (escalators beside the fountain: landmarks `Escada rolante que sobe` and `Escada rolante que desce`, and the leader may use either). All seated wins the round for the attackers; the 90 s timer running out ("acabaram os lugares na praça de alimentação") wins it for the defenders. Sides swap every round, so re-read `lunch.role` after each `served` or `full` event. First to 4 rounds. The warmup plays the same rounds without a point.
- Read `lunch` in `get_state`: `role` (`attacker`, `defender`), `attackersTeam`, `rules` (one sentence for your role), `secondsLeft`, `rush` (a rush hour: the round lasts half as long, 45 s, roughly one round in four), `seated`/`total`, `colleagues` (`name`, `state` `waiting`/`following`/`seated`, `leaderId`/`leaderName`, `pos`, `distance`, `bearingDeg`, `inUseReach`) and `restaurants` (`pos`, `distance`, `bearingDeg`, nearest first). Events are `k: lunch` with `what: follow | stop | seated | served | full`, `byName` and `colleague`. Each restaurant in `lunch.restaurants` has a `name` and `target`: only the one with `target: true` seats colleagues, and it changes every round.
- Rules: a waiting colleague follows the first living attacker holding USE within 80 units of it. Followers walk the leader's own path, so lead them the way you want them to go: up an escalator, not off the deck edge. A follower sits once within 180 units of a restaurant point on the same floor. A leader who dies or changes team leaves them waiting where they stand; any attacker can call them again from there.
- `hunt` plays the mode: attackers walk to the nearest waiting colleague and hold USE beside it, then lead to the nearest restaurant; defenders chase whoever leads a colleague, or patrol a ring around the waiting ones.
- `use` (`{ ms?: 1..10000 }`) calls by hand. It needs a waiting colleague with `inUseReach: true` and your team attacking, and answers `following` with the names that now follow you, or `interrupted` (round ended, died, timeout). One call can pick up all three, since they wait close together, and it ends early when an ally takes the last one in reach. Then `move_to` a restaurant `pos` or `hunt`. Only `hunt` calls colleagues by itself; a `move_to` walks past them.
- Attacking: one player leads, the others clear ahead on the escalator and in the food court, since a dead leader strands the colleagues mid-route. Defending: the leader is the target; once the colleagues stop, guard where they stand instead of their base.

## Debug defusion

Rules are defined in `shared/src/defuse.ts`, `server/src/bot.ts`, and `tools/mcp/view.ts`. In an MCP match on Escritório, `hunt` planted the bug and attempted defuses. A defuse interrupted by the player's death left the bug planted. The match timed out at 2–2 and the podium reported `winner: -1`.

- Mode `defuse`. One team attacks, the other defends, and sides swap after every point, so re-read `bomb.role` after each `defused` or `exploded` event. The bug is a laptop: attackers take it at their base, plant it at the site (the other team's base) and it explodes when the fuse runs out (point for the attackers); defenders defuse it (point for the defenders). First to 5 wins.
- Read `bomb` in `get_state`: `state` (`home`, `carried`, `planting`, `dropped`, `planted`), `role` (`attacker`, `defender`), `attackersTeam`, `carrierId`/`carrierName`, `defuserId`/`defuserName`, `pos` with `distance`/`bearingDeg`, `site` (`pos`, `distance`, `bearingDeg`), `secondsToExplosion`, `plantProgress`, `defuseProgress` (0..1). Events are `k: bomb` with `what: take | drop | return | plant | defuse | defused | exploded | expired | abandoned`.
- On Shopping Sul Rio, both debug defusion bases are on the Mirante. Read `bomb.home` and `bomb.site` for their `pos` and `floor`, and use `hunt` or take the escalators or glass lifts to the objective.
- The laptop closes and rides on the carrier's back. `bomb.stand` describes the solid crate at home or desk after planting. They block movement and bullets like map crates, so they work as cover. Walk around them and take or defuse from any side or corner.
- Black Friday hits about one round in five at a random moment, so it can switch on mid-round (at the latest when the bug is planted), shortening a fuse already burning to 15 s: it is "50% OFF" the normal 30 s fuse. It has its own sounds. Re-read `bomb.blackFriday` and `bomb.fuseSeconds` (15 s on Black Friday, 30 s otherwise) instead of trusting the round start.
- The attackers have a plant window (`bomb.secondsToPlant`, 60 s by default, `DEFUSE_PLANT_TIMEOUT_SECONDS`). If the bug is not planted in time nobody scores, the sides swap, the laptop goes to the other team with a different scenario and an `expired` event is sent, so re-read `bomb.role`. A plant already under way finishes.
- Rules: planting is holding USE (`E`) for 3 s inside the site (about 160 units from its centre); defusing is holding USE for 7 s within about 64 units of the planted bug. Letting go, dying or walking out resets the progress, only one player defuses at a time, and a defuse that would end after the fuse loses. Defenders cannot pick the bug up; a bug left on the floor for 20 s goes to the other team like an expired plant window (nobody scores, sides swap, `abandoned` event), so attackers must pick a dropped bug up fast and defenders only need to hold it off for 20 s. The objective also runs during `warmup` as practice that scores nothing, and pressing E where it cannot work shows the reason in the HUD (browser players only).
- `hunt` plays the objective: attackers fetch the bug, the carrier walks to the site and holds USE standing still, the rest escort the carrier; defenders patrol a ring around the site and, once it is planted, walk to the bug and hold USE. Attackers keep advancing while the nearest enemy is over 600 units away, then duel.
- `use` (`{ ms?: 1..10000 }`) holds USE while standing still and answers `planted`, `defused` or `interrupted` with a reason. Call it when you are already on the site or the bug and `hunt` would rather fight, then reissue `hunt`. Standing still makes you an easy target, so clear the area or ask for cover first.
- Defending: do not stack everyone on the bug; one defuses, the rest watch the doors. Attacking: once planted, guard the bug from cover instead of standing on it. The planter is pushed a step back off the desk that appears under the laptop, so expect your position to shift right after `planted`.
- Spread, hunt and keep moving (the user watches defuse matches and dislikes players parked on the point). Nobody holds one spot for more than about 5 s; shift to another cover point 100–200 units away with `move_to`, then back to `hunt`.
  - Defenders split by role, never all on the site: one anchor circles the site outside the plant radius; the others go out and hunt on the attackers' likely route (between their base `bomb.pos` while `home` and `bomb.site`, through `scene.doors` and `scene.landmarks`) to catch the carrier before the site, or set a crossfire at a choke from two angles. A trap is two players covering one door from different sides and swapping between two covers every few seconds, not a crouch-and-hold.
  - When the bug is planted, the nearest defender goes to defuse and the rest fall back to cover lanes into the site; when it is dropped, defenders deny it from cover around it: after 20 s on the floor the round goes to them.
  - Attackers do not walk in one clump: one goes ahead to clear, the carrier follows, one flanks by another door. Once planted, spread over the approaches to the desk and keep rotating between covers.
- Measured: `use {"ms":3500}` inside the site planted (`planted`), `use {"ms":7000}` next to a planted bug returned `defused`. `move_to` onto the bug or its stand often fails with "Target intersects solid map geometry"; shift the point about 45 units toward yourself. On Forja carriers kept dropping the bug crossing the `Bigorna` and several plant windows expired; send escorts on that route. 30 player-matches (3 Haiku 5.5 high on the broker, 3 Codex gpt-6.1-terra low on native MCP) ended mostly in timeout ties (1–1, 2–2).
- Defending as a trap (idea, not measured yet; the crouch-and-hold part was ruled out by the user because the players looked idle, so prefer a moving ring and never make it the default): under `hunt` the defenders stand on the site for 30–40 s, which is easy to spot and to shoot (seen in play: the hold also trips the frozen-pilot check, and `jump` does not move them). Instead of sitting on the point, spread around it and let the attackers walk in:
  - Take positions in a loose ring around `bomb.site`, a few hundred units out and outside the ~160-unit plant radius, one per approach (doors and lanes from `scene.doors` and `scene.landmarks`), each behind a crate or wall from `scene.cover`. Use `move_to` to a point 40–50 units off the crate, since a point on the crate fails ("Target intersects solid map geometry"), then `crouch` and hold.
  - The planter holds USE standing still for 3 s on the site, so that is the moment to shoot from two or three sides at once. Wait for the carrier to commit, do not engage at 600+ units where `hunt` drains the magazine.
  - Do not stack: at most one defender near the bug. Once it is planted, one player goes to defuse (within ~64 units, `use { ms: 7000 }`) while the others keep covering the lanes they hold, and the defuser starts early enough to finish before the fuse (7 s, so more than 7 s left).
  - Call it in chat so teammates take different lanes (`Plano: eu fecho a porta norte, você a leste, ninguém no ponto`). Reissue `hunt` once the round is decided or when the ring breaks, since `hunt` returns the pilot to the site.

- Callouts: `Levo o bug pro site`, `Bug plantado, cubram a entrada`, `Desarmando, me cubram!`, `Bug caiu em x,z`, `Faltam 10 s pra explodir`.
